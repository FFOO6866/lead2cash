# Deployment for Lead to Cash

This document describes the deployment architecture for rr.kailash.ai.

## Architecture

The deployment uses:
- **nginx** on the host for TLS termination and reverse proxy
- Docker containers for the application, PostgreSQL (pgvector), and Redis
- GitHub Actions for CI/CD with zero-downtime deployment
- GHCR (GitHub Container Registry) for image storage

## Docker Compose Files

| File | Purpose |
|------|---------|
| `docker-compose.yml` | **Production** - Supports both GHCR pull and local build |
| `docker-compose.local.yml` | **Development** - Local development with volume mounts |

### Production Compose (docker-compose.yml)

The production compose file supports two deployment modes:

1. **GHCR Mode** (default): Pulls pre-built image from GitHub Container Registry
2. **Local Build**: Falls back to local build if GHCR pull fails

```bash
# GHCR mode (recommended)
docker pull ghcr.io/integrum-global/rr_lead_to_cash/lead-to-cash:latest
docker-compose up -d

# Local build mode (fallback)
docker-compose build
docker-compose up -d
```

### Local Development (docker-compose.local.yml)

For local development with live code reloading:

```bash
docker-compose -f docker-compose.local.yml up -d
```

## nginx Configuration

The nginx configuration is at `deployment/nginx/lead-to-cash.conf`:
- Extended timeouts (180s) for `/agent/*` endpoints (LLM requests)
- Standard timeouts (60s) for other endpoints
- TLS via Let's Encrypt certbot

**Installation (one-time on server):**
```bash
sudo cp deployment/nginx/lead-to-cash.conf /etc/nginx/sites-available/
sudo ln -s /etc/nginx/sites-available/lead-to-cash.conf /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

## Deployment Process

Deployments are handled by `.github/workflows/deploy.yml`:

1. **Build & Push**: Builds Docker image and pushes to GHCR
2. **Deploy**: SSH to server, pull new image, restart containers
3. **Health Check**: Verifies deployment via `/health` endpoint

### Zero-Downtime Deployment

The deployment script ensures zero downtime:
1. Pre-deployment cleanup (build cache, temp files)
2. Pull new image while old app serves traffic
3. Replace containers with new image
4. Health check verification
5. Post-deployment cleanup

### Required GitHub Secrets

| Secret | Description |
|--------|-------------|
| `SSH_PRIVATE_KEY_B64` | Base64-encoded SSH key for server access |
| `GHCR_PAT` | GitHub Personal Access Token for GHCR |
| `POSTGRES_PASSWORD` | Database password |
| `REDIS_PASSWORD` | Redis password |
| `PERPLEXITY_API_KEY` | Perplexity API key for AI features |
| `OPENAI_API_KEY` | OpenAI API key for AI features |

### SSH Key Setup

```bash
# Generate key
ssh-keygen -t ed25519 -C "github-actions-deploy" -f ~/.ssh/github_deploy_key -N ""

# Base64 encode for GitHub Secrets
cat ~/.ssh/github_deploy_key | base64 -w 0
# Store output as SSH_PRIVATE_KEY_B64

# Add public key to server
cat ~/.ssh/github_deploy_key.pub >> ~/.ssh/authorized_keys
```

## Environment Variables

The `.env` file is automatically managed by the deployment workflow. Key variables:

```bash
ENVIRONMENT=production
DEBUG=false
LOG_LEVEL=INFO

# Database (auto-generated)
POSTGRES_USER=lead_to_cash
POSTGRES_PASSWORD=<from-secrets>
POSTGRES_DB=lead_to_cash
DATABASE_URL=postgresql://lead_to_cash:<password>@postgres:5432/lead_to_cash

# Redis (auto-generated)
REDIS_PASSWORD=<from-secrets>
REDIS_URL=redis://:<password>@redis:6379/0

# Security (auto-generated)
SECRET_KEY=<auto-generated>
JWT_SECRET_KEY=<auto-generated>

# APIs (from secrets)
PERPLEXITY_API_KEY=<from-secrets>
OPENAI_API_KEY=<from-secrets>

# CORS
CORS_ORIGINS=https://rr.kailash.ai
```

## Manual Deployment

For manual deployment without GitHub Actions:

```bash
# On the server
cd /opt/lead-to-cash

# Pull latest image
echo $GHCR_PAT | docker login ghcr.io -u integrum-global --password-stdin
docker pull ghcr.io/integrum-global/rr_lead_to_cash/lead-to-cash:latest

# Restart containers
docker-compose up -d --force-recreate lead-to-cash

# Verify
curl http://localhost:8000/health
```

## Troubleshooting

### Health Check Failing

```bash
# Check application logs
docker logs lead-to-cash-app --tail=100

# Check all services
docker-compose ps

# Check database connectivity
docker exec lead-to-cash-app python -c "from lead_to_cash.core.gateway import app; print('OK')"
```

### Disk Space Issues

The deployment includes automatic cleanup, but if needed:

```bash
# Remove unused images
docker image prune -af

# Remove build cache
docker builder prune -af

# Check disk usage
df -h /
```

### Timeout Errors on Chat UI

If you see 504 Gateway Timeout on `/agent/*` endpoints:

1. Verify nginx config has extended timeouts (180s)
2. Check nginx is reloaded: `sudo systemctl reload nginx`
3. Check application logs for slow LLM responses
